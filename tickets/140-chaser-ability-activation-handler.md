# 140: Server — ability-use counters + generic `useChaserAbility` activation handler

## Goal
Shared plumbing for every **active** Chaser ability (50/50, Skip, Double Time, Re-rack, Jumble — the ones the Chaser must deliberately trigger, per the design discussion's "passive they don't have to activate, active they do"). One authoritative message handler validates ownership/uses/timing and tracks the remaining-use counters; tickets 141 and 142 plug in the actual per-ability game effects. No visible gameplay effect on its own beyond the counters existing and a no-op activation being accepted/rejected correctly — this is intentionally a pure-infrastructure ticket.

## Scope
- `server/src/rooms/schema/GameState.ts`: add synced counters (visible to all clients is fine and desirable here — these aren't answers or hidden info, same reasoning as the Chaser pot being public):
  - `@type("uint8") fiftyFiftyUsesRemaining` (default from `CHASER_ABILITIES.fiftyFifty.usesPerGame`)
  - `@type("uint8") skipUsesRemaining` (default from `CHASER_ABILITIES.skip.usesPerGame`)
  - `@type("uint8") pushbackImmunityUsesRemaining` (default from `CHASER_ABILITIES.pushbackImmunity.usesPerGame` — only meaningful when Bezos is the Chaser, but harmless to always carry; ticket 142 consumes it)
  - `@type("boolean") doubleTimeUsedThisTableRound`, `@type("boolean") reRackUsedThisTableRound`, `@type("boolean") jumbleUsedThisTableRound` — reset to `false` whenever a new contestant's Chase starts (wire the reset into the `startChase` effect in `effects.ts`, alongside where `boardPos` is set for the new round).
  - `@type("boolean") doubleTimeArmed` — transient, true from activation until the next chase-question resolves (consumed either way); reset to `false` in `resolveChaseQuestion` and in `startNextChaseQuestion`/`clearChaseAnswerTimer` so it never survives past the question it was armed for.
- New module `server/src/rooms/handlers/chaserAbilities.ts` (mirrors the existing small dedicated modules like `chaserSelection.ts`):
  - A small ownership table: which ability ids belong to which `chaserCharacterId` (`fiftyFifty`/`skip` → any character; `doubleTime` → `"big stan"` only; `reRack` → `"nami"` only; `jumble` → `"maggie"` only).
  - `canUseAbility(room, seatId, abilityId): { ok: true } | { ok: false, reason: string }` — pure-ish validation (reads room state, doesn't mutate): sender must be the Chaser; ability must be in `["fiftyFifty", "skip", "doubleTime", "reRack", "jumble"]` (the only ones with manual activation — `noMiddle`/`pushbackImmunity`/`timeBonus`/`shortFuse`/`silence` are passive and never reach this handler, per ticket 139); ability must be owned (shared or matching character); the relevant uses-remaining counter must be > 0 (or the per-table-round flag must still be `false`); and a **phase/timing gate** per ability:
    - `fiftyFifty`, `reRack`, `jumble`: `currentPhase === Chase`, `room.currentChaseQuestion` exists, and `Object.keys(room.chaseAnswers).length === 0` (nobody has answered the current question yet — redrawing or altering a question after either side has committed would be exploitable/confusing).
    - `doubleTime`: `currentPhase === Chase`, `room.currentChaseQuestion` exists, `!('chaser' in room.chaseAnswers)` (the Chaser hasn't submitted their own answer to this question yet — the contestant may already have, that's fine, Double Time only concerns the Chaser's own correctness), and not already armed.
    - `skip`: `currentPhase === ChaserFinal`, a current chaser-final question exists (`!room.finalChaserQuestionResolved`), and no steal window is currently open (`!room.finalStealActive`).
  - `applyChaserAbilityEffect(room, abilityId)` — the actual per-ability mutation. **This ticket implements only the counter/flag bookkeeping** (decrement the uses-remaining counter, or set the per-table-round/armed boolean); leave a clear extension point (e.g. a `switch` with a `// ticket 141/142` comment on the branches for `fiftyFifty`/`doubleTime`/`reRack`/`jumble`/`skip`) for the next two tickets to fill in the real board/final-round mutation. Do not implement 50/50's option removal, Double Time's board math, Re-rack's redraw, Jumble's shuffle, or Skip's question-discard here — those are tickets 141/142's scope.
- `server/src/rooms/handlers/messageHandlers.ts`: add `useChaserAbility(client, message, room)` — validates `message.ability` is a string, calls `canUseAbility`, rejects (log + return, same pattern as every other handler) on failure, otherwise calls `applyChaserAbilityEffect` and broadcasts a public `chaserAbilityUsed { ability, seatId }` event (no hidden info — this is a "the Chaser just did a thing" cue for the UI, same spirit as the existing `reaction` broadcast).
- `server/src/rooms/TriviaRoom.ts`: register the `useChaserAbility` message in the `messages` record with the same rate-limit-then-delegate pattern as every other entry.
- Reset `pushbackImmunityUsesRemaining`/`fiftyFiftyUsesRemaining`/`skipUsesRemaining` once per game (they're already only ever set at `GamePlayer`/`GameState` construction time — no mid-game reset needed since there's one Chaser per room for the whole game).

## Acceptance
- `cd server && npm test` and `npm run build` pass.
- New tests in `server/test/` cover: a non-Chaser client is rejected; an ability not owned by the current character is rejected (e.g. Nami's client sending `doubleTime`); an ability used with 0 charges remaining is rejected; `fiftyFifty`/`reRack`/`jumble` are rejected once `chaseAnswers` is non-empty; `doubleTime` is rejected once the Chaser has already answered the current chase question; `skip` is rejected outside `ChaserFinal` and while a steal window is open; a valid activation decrements the right counter/sets the right flag and broadcasts `chaserAbilityUsed`; the per-table-round flags reset when `startChase` fires for the next contestant.
