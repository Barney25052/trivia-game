# 141: Server — board-chase abilities (50/50, Double Time, Re-rack, Jumble)

## Goal
Wires the real game effects for the four board-chase-phase active abilities into the `applyChaserAbilityEffect` extension point ticket 140 left open. This is where the abilities actually change the chase.

## Scope
All changes in `server/src/rooms/TriviaRoom.ts` / `server/src/rooms/handlers/chaserAbilities.ts` (the module ticket 140 created).

- **50/50** (shared, any character, 4 uses/game): removes one *incorrect* option from `currentChaseQuestion` and re-broadcasts the narrowed question to everyone. Both the contestant and the Chaser currently see and answer the same shared question/options (confirmed in `TriviaRoom.startNextChaseQuestion`/`submitChaseAnswer` — there's no per-recipient option split today), so this is a **mutual-benefit, double-edged** ability by design: using it makes the question easier for both sides simultaneously. That's a deliberate reading of "the Chaser plays a 50/50" (raises their own odds at the cost of also helping the contestant catch up) — call this out explicitly as the chosen design in a code comment, since a future ticket could split per-recipient views to make it Chaser-only, but that's out of scope here. Mechanically: pick a random wrong option to drop, adjust `correctIndex` on the server-held question to match the new (shorter) options array, and broadcast an updated `question` payload with the narrowed `options`. Guard: can only be used once per question (already enforced by ticket 140's "chaseAnswers must be empty" gate, since a second use would need a new question).
- **Double Time** (Big Stan only, 1/table round): activating sets `doubleTimeArmed = true` (ticket 140's flag). In `resolveChaseQuestion`, when resolving the Chaser's side:
  - Correct **and armed**: off-board (`boardPos === BOARD.chaserStartOffboard`) → move to `BOARD.chaserFirstCorrectSpace - 1` (skip a space instead of the normal single first-correct move); otherwise → `Math.max(BOARD.escapeSpace, boardPos - 2)`.
  - Wrong **and armed** and already on-board (`boardPos <= BOARD.chaserFirstCorrectSpace`, i.e. not still at the off-board starting value): retreat one space, capped so it never goes fully back off-board — `boardPos = Math.min(BOARD.chaserFirstCorrectSpace, boardPos + 1)`.
  - Wrong **and armed** and still off-board: no extra penalty (nothing to retreat from) — same as an unarmed miss.
  - Clear `doubleTimeArmed` back to `false` after resolving, whether the question was answered correctly, wrongly, or the lockout window simply expired with the Chaser never answering (this counts as "wrong" for arming purposes).
  - Broadcast should let the client distinguish a Double-Time-affected move from a normal one (e.g. include `doubleTimeArmed` in the existing `chaseQuestionResult` broadcast) so ticket 146 can show a distinct outcome banner.
- **Re-rack** (Nami only, 1/table round): discards `currentChaseQuestion` and immediately draws + broadcasts a fresh one via the same path `startNextChaseQuestion` already uses — this is functionally "redraw now" rather than a new code path. Sets `reRackUsedThisTableRound = true`.
- **Jumble** (Maggie only, 1/table round): the contestant's own client shows the current question's answer buttons in a shuffled order, while the underlying `answerIndex` semantics stay unchanged for scoring (avoids touching `correctIndex`/`resolveChaseQuestion` at all). Implementation: generate a permutation of `[0..options.length)`, store it against the current question, and send it **only to the active contestant's client** as an extra field on a targeted `client.send("question", {...payload, displayOrder})` (everyone else — Chaser, spectators — keeps getting the normal broadcast with no `displayOrder`, i.e. natural order). The contestant's client is expected (ticket 146) to render buttons in `displayOrder` order but submit the *real* index (`displayOrder[clickedPosition]`) — this ticket only needs to deliver the permutation; ticket 146 consumes it. Sets `jumbleUsedThisTableRound = true`. Only usable before anyone has answered (already gated by ticket 140), so there's no risk of the permutation changing mid-answer.

## Acceptance
- `cd server && npm test` and `npm run build` pass.
- Tests cover: 50/50 narrows a 3-option question to 2 and the remaining correct index still resolves correctly; Double Time's four cases (correct off-board, correct on-board, wrong on-board, wrong off-board) each produce the exact board-position math above, and the flag clears after one question regardless of outcome; Re-rack replaces the current question (different id) and does not touch board positions or the answer counters; Jumble's targeted send reaches only the active contestant's client (not the Chaser's, not a spectator's) and the permutation is a valid shuffle of the real option indices; submitting `answerIndex` still resolves against the true `correctIndex` regardless of any client-side jumble.
- A full chase round using each ability once (via `roomFlow`-style integration test) still ends in a valid `chaseEscape`/`chaseCaught` dispatch.
